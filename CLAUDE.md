# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

WPF-приложение (net10.0-windows) для записи звонков: микширует системный звук (WASAPI loopback) и микрофон в MP3, ведёт живую транскрипцию на русском (sherpa-onnx + GigaAM v3 + Silero VAD) и формирует итоги встречи через локальный Ollama. Весь UI, комментарии и строки — на русском языке; придерживайся этого стиля.

## Команды

```powershell
dotnet build
dotnet run
```

Тестов нет. Вместо них — скрытые CLI-режимы самопроверки (приложение — WinExe, консоли нет, результат пишется в лог-файл; первая строка лога — `OK` или `FAIL`):

```powershell
# Запись N секунд без окна (проверка аудиотракта)
CallAudioRecorder.exe --selftest <лог-файл> [секунды]

# Замер скорости распознавания (RTF) GigaAM v3 на WAV-файле
CallAudioRecorder.exe --stt-test <лог-файл> <wav-файл>

# Самотест диаризации: два WAV с разными голосами → «Собеседник 1»/«Собеседник 2»
CallAudioRecorder.exe --diar-test <лог-файл> <wav1> <wav2>

# Сквозной тест: запись + живая транскрипция N секунд
CallAudioRecorder.exe --stt-selftest <лог-файл> [секунды]

# Итоги встречи по тестовому транскрипту через Ollama
CallAudioRecorder.exe --summary-test <лог-файл> <модель>

# LLM-коррекция транскрипта с искажёнными английскими терминами
CallAudioRecorder.exe --fix-test <лог-файл> <модель>
```

Режимы объявлены в `App.xaml.cs` (`OnStartup`). STT-режимы требуют скачанных моделей, `--summary-test`/`--fix-test` — запущенного Ollama на `localhost:11434`.

## Архитектура

Конвейер: **RecordingEngine** (аудио → MP3 + tap-потоки) → **TranscriptionService** (tap'ы → реплики) → **OllamaClient** + **SummaryPrompt** / **TranscriptCorrector** (транскрипт → итоги / исправленный текст). `MainWindow.xaml.cs` связывает всё это с UI (MVVM не используется — code-behind).

### RecordingEngine.cs — запись

Два захвата WASAPI (loopback + микрофон) → `BufferedWaveProvider` → ресемпл в 48 kHz stereo → `MixingSampleProvider` → LAME MP3. Ключевой инвариант: поток записи вытягивает из микшера ровно столько кадров, сколько прошло по `Stopwatch` (clock-driven pull), а `ReadFully = true` заполняет пустые буферы тишиной — поэтому паузы системного звука не «съедаются» и потоки не разъезжаются. При `enableTranscriptionTaps` дополнительно отдаёт `MicTap16k`/`SystemTap16k` (16 kHz mono float) для распознавания.

### Services/TranscriptionService.cs — живая транскрипция

Два «насоса» (по потоку на канал) читают tap'ы со скоростью реального времени — благодаря нулям тишины индекс сэмпла = время записи. Каждый насос кормит свой Silero VAD; сегменты расширяются на 0.3 с в обе стороны через кольцевой буфер `AudioRing` (VAD режет впритык) и складываются в общую очередь, которую разбирает **один** `OfflineRecognizer` (чтобы не выедать CPU у MP3-пути). Спикеры жёстко именуются: микрофон = «Я», система = «Собеседник» или «Собеседник N» при диаризации (`TranscriptEntry.IsMe` завязан на строку «Я»).

Hotwords работают только с transducer + `modified_beam_search` и только кириллицей — словарь GigaAM почти не содержит латиницы (85 токенов из 1025). Английские термины поэтому неизбежно искажаются («эйпиай», «дед лайн»); их восстанавливает LLM-коррекция (`TranscriptCorrector`), а не параметры распознавателя — не пытайся чинить это на стороне ASR.

Диаризация (`Services/SpeakerDiarizer.cs`, опциональна): реплики системного канала помечаются «Собеседник 1», «Собеседник 2», … — embedding голоса (CAM++ zh+en) на каждый распознанный сегмент, сопоставление с профилями по косинусной близости (порог 0.6; один голос ≈ 0.8+, разные ≈ 0.5 — калибровано по `--diar-test`). Сегменты короче 2 с не создают нового спикера и не уточняют центроид — только прилипают к ближайшему профилю (шумный embedding). Вызывается только из потока SttWorker (не потокобезопасен); нет модели на диске или ошибка — диаризация молча выключается, остаётся общий «Собеседник». Включается чекбоксом «Различать собеседников по голосу» (по умолчанию вкл, поле `diarizeSpeakers` в settings.json). Внимание: цвета имён спикеров в пузырях — это DataTrigger'ы в `MainWindow.xaml` по ТОЧНЫМ строкам «Собеседник 1»…«Собеседник 4»; при переименовании меток в `SpeakerDiarizer` нужно править и XAML.

### Services/* — LLM-слой

- `OllamaClient` — стриминговый чат с локальным Ollama; типизированные ошибки `OllamaUnavailableException` / `OllamaModelMissingException` показываются в статусе как есть.
- `TranscriptCorrector` — исправление транскрипта в формате `[номер] текст`; при не-формате в ответе LLM исходный транскрипт возвращается нетронутым. Там же `ToHotwords` — фильтрует глоссарий до кириллицы.
- `ModelDownloader` — докачка моделей (~262 МБ: GigaAM с HuggingFace + зеркало, VAD и CAM++ с GitHub releases) в `%LOCALAPPDATA%\CallAudioRecorder\models` с валидацией по минимальному размеру. Тег релиза speaker-модели содержит реальную опечатку «recongition» — не «исправлять».

### Файлы результатов

Рядом с `Запись_*.mp3` сохраняются `*.транскрипт.md` и `*.итоги.md`. Настройки UI — в `%LOCALAPPDATA%\CallAudioRecorder\settings.json`.

## Особенности потоков

Фоновые потоки не бросают исключения наружу — складывают их в свойство `Error`, которое UI опрашивает по таймеру (80 мс). `TranscriptionService.EntryRecognized` вызывается на фоновом потоке — в UI обязательно через `Dispatcher`.
