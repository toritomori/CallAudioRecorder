# Call Recorder

*[Русский](README.md) · English*

A Windows desktop app that records a call to MP3 (system audio + microphone), produces a **live Russian or English transcript fully offline**, and turns it into meeting notes with a local LLM. Nothing leaves your machine — speech recognition runs on sherpa-onnx, the summary is generated by Ollama on the same computer.

![.NET](https://img.shields.io/badge/.NET-10.0--windows-512BD4) ![WPF](https://img.shields.io/badge/UI-WPF-blue) ![offline](https://img.shields.io/badge/STT-offline-success)

> The interface is in Russian. The transcript and the meeting notes follow the language you record in: pick Russian or English before you start.

## Features

- **Two sources at once** — system audio (what you hear) plus the microphone, mixed into a single MP3 at 128/192/320 kbps, with separate volume sliders and level meters.
- **Single-app audio** — instead of the whole output device you can record one window (Zoom, a browser, Telegram), so notifications and music from other programs stay out of the recording. Windows currently playing audio are marked with a «♪» in the source list.
- **Live transcript** — utterances appear while you are still talking, split by speaker: yours are labelled «Я» (me), the far end «Собеседник» (the other party).
- **Russian and English** — the language is chosen before recording: Russian runs on GigaAM v3, English on Parakeet TDT 0.6B. In English mode the speakers are "Me" and "Speaker N", and the notes and text correction come out in English too. The model for a language is downloaded the first time you pick it.
- **Voice-based speaker separation** — with several people on the other end, utterances are marked «Собеседник 1», «Собеседник 2», … (diarization by voice embedding, toggled by a checkbox).
- **Meeting glossary** — a list of terms and names that helps both recognition and the later text correction.
- **LLM text correction** — restores the English terms that a Russian acoustic model inevitably mangles («эйпиай» → «API», «дед лайн» → «deadline»).
- **Meeting notes** — summary, decisions, a task table with owners and deadlines, open questions and next steps; streamed as they are generated and saved to a file.
- **Everything local** — models are downloaded once, after which no internet is needed (apart from the call itself).

## Requirements

- Windows 10/11
- [.NET 10 SDK](https://dotnet.microsoft.com/download) (to build)
- ~300 MB of disk space for the recognition models (another ~660 MB if you need English)
- For notes and text correction — [Ollama](https://ollama.com/) on `localhost:11434` with any instruction-tuned model that handles Russian well (`qwen3.5:9b` is preselected)

## Build and run

```powershell
dotnet build
dotnet run
```

The first time transcription is enabled, the app downloads the models itself (~262 MB) into `%LOCALAPPDATA%\CallAudioRecorder\models`; progress is shown in the status bar. If the download fails, recording still works — only without a transcript.

## Usage

1. Pick where the other party's audio comes from: «Всё устройство вывода» (the whole output device — then choose the speakers/headset below) or the window of a specific app; the list is rebuilt every time you open it. Then pick the microphone. The system defaults are preselected.
2. Adjust channel volumes, bitrate and the output folder if needed.
3. Leave «Живой транскрипт» (live transcript) and «Различать собеседников по голосу» (tell speakers apart by voice) enabled if you want a transcript, and pick the spoken language — «Русский» or English.
4. Type the terms and names that will come up during the meeting into the glossary, comma-separated.
5. Press the big record button. The timer and the level meters confirm audio is flowing; utterances show up on the «Транскрипт» tab.
6. Stop with the same button. The app finalizes the MP3 and recognizes the remaining speech.
7. **«Исправить текст»** (fix text) — runs the transcript through Ollama and rewrites it with the corrected version.
8. **«Сформировать итоги»** (make notes, on the «Итоги» tab) — builds the structured meeting summary.

## Output files

Next to the recording, in the folder you chose:

```
Запись_2026-07-24_15-30-00.mp3
Запись_2026-07-24_15-30-00.транскрипт.md
Запись_2026-07-24_15-30-00.итоги.md
```

UI settings (utterance merge gap, glossary, diarization) live in `%LOCALAPPDATA%\CallAudioRecorder\settings.json`.

## How it works

```
RecordingEngine ──► MP3 (48 kHz stereo)
      │
      ├─ MicTap16k ──┐
      └─ SysTap16k ──┴─► TranscriptionService ──► utterances ──► UI
                          (VAD → ASR → diarization)                │
                                                                   ▼
                                              TranscriptCorrector / SummaryComposer
                                                          (Ollama)
```

| File | Role |
| --- | --- |
| `RecordingEngine.cs` | System audio (device or single app) plus microphone → resampling → mixer → LAME MP3. The recording thread pulls exactly as many frames from the mixer as the `Stopwatch` says have elapsed, and empty buffers are filled with silence — so gaps in system audio are not swallowed and the channels never drift apart. Also exposes 16 kHz mono tap streams for recognition. |
| `Services/ProcessLoopbackCapture.cs` | Captures one application's audio (Windows Application Loopback) behind a plain `IWaveIn`: activation on «VAD\Process_Loopback», the whole process tree, all COM confined to a single MTA thread. |
| `Services/AudioWindows.cs` | The list of candidate windows, marking the ones currently playing audio. |
| `Services/LanguageProfile.cs` | The language profile: model, speaker labels, glossary filter — the single place where language differences live. |
| `Services/TranscriptionService.cs` | One "pump" per channel: Silero VAD cuts speech into segments, a single shared `OfflineRecognizer` (GigaAM v3, transducer + punctuation) recognizes them. Segments are padded by 0.3 s on both sides through a ring buffer. |
| `Services/SpeakerDiarizer.cs` | A voice embedding (CAM++ zh+en) per segment of the system channel, matched against speaker profiles by cosine similarity. |
| `Services/OllamaClient.cs` | Streaming chat with a local Ollama, with typed "no server" / "no model" errors. The context window is sized to the prompt; cloud models are never forced to a local `num_ctx`. |
| `Services/TranscriptCorrector.cs` | LLM transcript correction in batches (the answer is as long as the input); if the reply comes back in an unexpected format, the original text is left untouched. |
| `Services/SummaryComposer.cs` | Notes that respect the model's window: a short meeting goes in one request, a long one is condensed part by part and summarized from those condensates. |
| `Services/SummaryPrompt.cs` | The meeting-notes prompt with its fixed section structure. |
| `Services/ModelDownloader.cs` | Downloads models from HuggingFace (plus a mirror) and GitHub releases, validating them by size. |
| `MainWindow.xaml(.cs)` | Dark chromeless UI, code-behind (no MVVM). |

### Models

| Model | Purpose | Size |
| --- | --- | --- |
| GigaAM v3 (transducer + punct) | Russian speech recognition | ~230 MB |
| Parakeet TDT 0.6B v2 (int8) | English speech recognition | ~660 MB |
| Silero VAD | voice activity detection | ~2 MB |
| CAM++ (3D-Speaker, zh+en) | voice embedding for diarization | ~28 MB |

### Known limitations

- In Russian mode English terms come out transliterated into Cyrillic, phonetically: the GigaAM vocabulary barely contains Latin script. No ASR setting fixes this — LLM correction («Исправить текст») does.
- The recognition language is fixed for the whole recording: mixed Russian/English speech in one call is not separated — record in whichever language dominates.
- Single-app recording relies on Windows Application Loopback; on very old Windows 10 builds it may be unavailable, in which case the app says so when you start recording and the output-device route remains.
- Diarization confuses similar voices, and segments shorter than 2 s never create a new speaker — short utterances stick to the nearest profile.
- Without Ollama you still get recording and the transcript; notes and correction report an error in the status bar.

## Self-tests

There are no unit tests — hidden CLI modes take their place. The app is built as `WinExe` and has no console, so results go to a log file whose first line is either `OK` or `FAIL`.

```powershell
# Record N seconds with no window — audio path check
CallAudioRecorder.exe --selftest <log-file> [seconds]

# Recognition speed (RTF) on a WAV file, language ru or en
CallAudioRecorder.exe --stt-test <log-file> <wav-file> [ru|en]

# Diarization: two WAVs with different voices → «Собеседник 1»/«Собеседник 2»
CallAudioRecorder.exe --diar-test <log-file> <wav1> <wav2>

# End-to-end: recording plus live transcription for N seconds
CallAudioRecorder.exe --stt-selftest <log-file> [seconds] [ru|en]

# Meeting notes from a sample transcript
CallAudioRecorder.exe --summary-test <log-file> <model>

# LLM correction of a transcript with mangled terms
CallAudioRecorder.exe --fix-test <log-file> <model> [ru|en]

# Notes from a synthetic transcript of a long meeting — context window check
CallAudioRecorder.exe --summary-long-test <log-file> <model> [minutes] [ru|en]

# Render the window to PNG and check the layout for overlapping blocks
CallAudioRecorder.exe --ui-shot <png-file> <log-file>

# Single-app audio capture; PID=0 prints the list of candidate windows
CallAudioRecorder.exe --proc-loopback-test <log-file> [PID] [seconds] [all|direct|engine]
```

The STT modes need the models downloaded; `--summary-test`, `--fix-test` and `--summary-long-test` need Ollama running. The last one only reports `OK` when the reply contains all five sections of the notes and ends with `done_reason=stop`.

## Privacy

Recording, recognition and note-taking all happen on your machine. The network is used exactly once — to download the models. Note that recording a conversation may require the consent of the other participants; the rules depend on your jurisdiction.
