# Call Recorder

Настольное приложение для Windows: записывает звонок в MP3 (системный звук + микрофон), ведёт **живую транскрипцию на русском полностью офлайн** и формирует итоги встречи локальной LLM. Ничего не уходит в облако — распознавание работает на sherpa-onnx, итоги считает Ollama на вашей же машине.

![.NET](https://img.shields.io/badge/.NET-10.0--windows-512BD4) ![WPF](https://img.shields.io/badge/UI-WPF-blue) ![offline](https://img.shields.io/badge/STT-offline-success)

## Возможности

- **Запись двух источников сразу** — WASAPI loopback (то, что вы слышите) + микрофон, микшируются в один MP3 128/192/320 kbps с раздельными регуляторами громкости и индикаторами уровня.
- **Живой транскрипт** — реплики появляются прямо во время разговора, разделённые по спикерам: ваши — «Я», собеседника — «Собеседник».
- **Разделение собеседников по голосу** — при нескольких участниках на том конце реплики помечаются «Собеседник 1», «Собеседник 2», … (диаризация по embedding'у голоса, включается чекбоксом).
- **Глоссарий встречи** — список терминов и имён, который помогает и распознаванию, и последующей коррекции текста.
- **Исправление текста через LLM** — восстанавливает английские термины, которые русская акустическая модель неизбежно ломает («эйпиай» → «API», «дед лайн» → «deadline»).
- **Итоги встречи** — резюме, решения, таблица задач с ответственными и сроками, открытые вопросы и следующие шаги; генерируются потоково, с сохранением в файл.
- **Всё локально** — модели скачиваются один раз, дальше интернет не нужен (кроме, собственно, самого звонка).

## Требования

- Windows 10/11
- [.NET 10 SDK](https://dotnet.microsoft.com/download) (для сборки)
- ~300 МБ на диске под модели распознавания
- Для итогов и коррекции текста — [Ollama](https://ollama.com/) на `localhost:11434` с любой инструктивной моделью, хорошо знающей русский (по умолчанию подставляется `qwen3.5:9b`)

## Сборка и запуск

```powershell
dotnet build
dotnet run
```

При первом включении транскрипции приложение само докачает модели (~262 МБ) в `%LOCALAPPDATA%\CallAudioRecorder\models`; прогресс виден в строке состояния. Если загрузка не удалась — запись всё равно пойдёт, но без транскрипта.

## Как пользоваться

1. Выберите устройство вывода (динамики/гарнитуру, с которых идёт звук собеседника) и микрофон. По умолчанию подставляются системные устройства по умолчанию.
2. При необходимости подстройте громкость каналов, битрейт и папку сохранения.
3. Оставьте включёнными «Живой транскрипт» и «Различать собеседников по голосу», если нужна расшифровка.
4. Впишите в глоссарий термины и имена, которые прозвучат на встрече — через запятую.
5. Нажмите большую кнопку записи. Таймер и индикаторы покажут, что звук идёт; реплики будут появляться во вкладке «Транскрипт».
6. Остановите запись той же кнопкой. Приложение допишет MP3 и распознает остаток речи.
7. **«Исправить текст»** — прогонит транскрипт через Ollama и перезапишет его исправленной версией.
8. **«Сформировать итоги»** (вкладка «Итоги») — соберёт структурированное резюме встречи.

## Файлы результатов

Рядом с записью в выбранной папке появляются:

```
Запись_2026-07-24_15-30-00.mp3
Запись_2026-07-24_15-30-00.транскрипт.md
Запись_2026-07-24_15-30-00.итоги.md
```

Настройки UI (порог склейки реплик, глоссарий, диаризация) хранятся в `%LOCALAPPDATA%\CallAudioRecorder\settings.json`.

## Как это устроено

```
RecordingEngine ──► MP3 (48 kHz stereo)
      │
      ├─ MicTap16k ──┐
      └─ SysTap16k ──┴─► TranscriptionService ──► реплики ──► UI
                          (VAD → ASR → диаризация)              │
                                                                ▼
                                              TranscriptCorrector / SummaryPrompt
                                                        (Ollama)
```

| Файл | Роль |
| --- | --- |
| `RecordingEngine.cs` | Два захвата WASAPI → ресемпл → микшер → LAME MP3. Поток записи вытягивает из микшера ровно столько кадров, сколько прошло по `Stopwatch`, а пустые буферы заполняются тишиной — поэтому паузы системного звука не «съедаются» и каналы не разъезжаются. Отдаёт tap-потоки 16 kHz mono для распознавания. |
| `Services/TranscriptionService.cs` | По «насосу» на канал: Silero VAD режет речь на сегменты, общий `OfflineRecognizer` (GigaAM v3, transducer + пунктуация) их распознаёт. Сегменты расширяются на 0.3 с в обе стороны через кольцевой буфер. |
| `Services/SpeakerDiarizer.cs` | Embedding голоса (CAM++ zh+en) на каждый сегмент системного канала, сопоставление с профилями по косинусной близости. |
| `Services/OllamaClient.cs` | Стриминговый чат с локальным Ollama, типизированные ошибки «нет сервера» / «нет модели». |
| `Services/TranscriptCorrector.cs` | Коррекция транскрипта LLM; при неожиданном формате ответа исходный текст остаётся нетронутым. |
| `Services/SummaryPrompt.cs` | Промпт итогов встречи с жёсткой структурой разделов. |
| `Services/ModelDownloader.cs` | Докачка моделей с HuggingFace (+ зеркало) и GitHub releases, с валидацией по размеру. |
| `MainWindow.xaml(.cs)` | Тёмный безрамочный UI, code-behind (MVVM не используется). |

### Модели

| Модель | Назначение | Размер |
| --- | --- | --- |
| GigaAM v3 (transducer + punct) | распознавание русской речи | ~230 МБ |
| Silero VAD | детектор речи | ~2 МБ |
| CAM++ (3D-Speaker, zh+en) | embedding голоса для диаризации | ~28 МБ |

### Известные ограничения

- Английские термины распознаются кириллицей и на слух: словарь GigaAM почти не содержит латиницы. Это лечится не настройками ASR, а LLM-коррекцией («Исправить текст»).
- Диаризация путает похожие голоса, а сегменты короче 2 с не создают нового спикера — короткие реплики прилипают к ближайшему профилю.
- Без Ollama доступна только запись и транскрипт; итоги и коррекция сообщат об ошибке в строке состояния.

## Самопроверка

Юнит-тестов нет — вместо них скрытые CLI-режимы. Приложение собрано как `WinExe`, консоли нет, поэтому результат пишется в лог-файл; первая строка — `OK` или `FAIL`.

```powershell
# Запись N секунд без окна — проверка аудиотракта
CallAudioRecorder.exe --selftest <лог-файл> [секунды]

# Скорость распознавания (RTF) GigaAM v3 на WAV-файле
CallAudioRecorder.exe --stt-test <лог-файл> <wav-файл>

# Диаризация: два WAV с разными голосами → «Собеседник 1»/«Собеседник 2»
CallAudioRecorder.exe --diar-test <лог-файл> <wav1> <wav2>

# Сквозной тест: запись + живая транскрипция N секунд
CallAudioRecorder.exe --stt-selftest <лог-файл> [секунды]

# Итоги встречи по тестовому транскрипту
CallAudioRecorder.exe --summary-test <лог-файл> <модель>

# LLM-коррекция транскрипта с искажёнными английскими терминами
CallAudioRecorder.exe --fix-test <лог-файл> <модель>
```

STT-режимам нужны скачанные модели, `--summary-test` и `--fix-test` — запущенный Ollama.

## Приватность

Запись, распознавание и итоги выполняются на вашей машине. Сеть используется только один раз — для загрузки моделей. Учтите, что запись разговоров может требовать согласия собеседников: правила зависят от вашей юрисдикции.
